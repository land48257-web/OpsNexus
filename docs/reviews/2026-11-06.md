# 平台审查与修复记录（2026-11-06）

## 结论与范围

按维护者确认的定位，平台继续面向可信内部运维环境，本轮不扩展角色或资产权限体系。保留 Go 单体 + 嵌入 React 的架构，重点修复操作失败、结果失真、连接中断、配置失效及构建不可复现的问题。

检查覆盖启动配置、登录、全部已注册及未注册的 handler、SQL/Redis/MongoDB/SSH/SFTP 服务、前端请求与状态、构建打包、依赖扫描和现有文档。内置 DM 驱动做了静态分析和定点修复，并未验证其全部协议、容灾和外部加密库行为。

初始工作区无未提交变更。测试均使用本地隔离配置、内存服务或 mock；未使用工作区实际配置中的凭证连接生产资产，未执行外部数据库写入、部署或发布。

## 验证记录

最终检查结果如下；测试结果仅覆盖本次代码和当前工具链。

- Go 工具链：1.27.3；项目最低版本因依赖要求提升至 1.26.0。
- Node.js：24.21.0；项目要求 22.13+。
- `go test ./...`：通过。
- `go test -race ./...`：通过；后续修改另对受影响的业务包、工具包及 DM 包复测。
- `go vet ./cmd/... ./internal/... ./pkg/dbutil ./pkg/gormdm ./pkg/logger ./pkg/mongoutil ./pkg/sqlutil ./pkg/sshutil ./web`：业务代码检查通过。
- 完整 `go vet ./...`：仍未通过，剩余 **26 条全部来自内置 DM 驱动**：21 条生成解析器不可达代码、3 条重连/备用连接复制锁、2 条外部加密库 `unsafe.Pointer` 使用。未通过关闭检查器来隐藏这些结果。
- `npm --prefix web run lint`：通过。
- `npm --prefix web test`：10 项回归测试通过。
- 前端根路径及 `/devops/` 生产构建：通过；Monaco 大资源块警告仍存在。
- `./build.sh`：Linux amd64、Linux arm64、Windows amd64 构建通过。交叉编译不等于在这些操作系统上完成运行验收。
- `npm audit`：从初始 15 项告警降至 0。`dompurify`、`minimatch` 使用显式 overrides；将来升级 Monaco/TypeScript ESLint 时应重新评估 overrides。
- `govulncheck`：从初始 16 项静态可达报告降至 0；仍报告未发现调用链的 package/module 级告警（分别 3/10，可能重叠）。这不等于证明所有依赖无漏洞。
- 浏览器：根路径及 `/devops/` 均通过。使用本机 Chrome、临时管理员配置，真实加载嵌入页面及 worker；SQL API 用测试响应验证编辑、Ctrl+Enter、SSE 事务结果。未接入真实数据库。

依赖更新依据扫描结果和上游报告，例如 Go 官方的 [SSH 连接死锁报告 GO-2026-6355](https://pkg.go.dev/vuln/GO-2026-6355)。MongoDB driver v1 仅做补丁更新，未迁移到 v2。

## 升级注意

1. 使用 Go 1.26+、Node 22.13+，以锁文件重新安装前端依赖。
2. 配置必须可读取、至少有一个管理员、JWT secret 非空、资产 ID 唯一。旧配置中被忽略的错误现在会阻止启动。
3. 示例配置改为根路径；已有 `/devops` 部署保持配置前缀，并用相同 `VITE_BASE_PATH` 重新构建。
4. 前后端必须一起更新：终端改为二进制数据帧和连接控制帧，SQL 增加最终事务事件，登录响应增加超时配置。
5. UI 的 SQL 默认遇错停止并回滚；取消选项后继续执行。DDL 隐式提交依旧受数据库规则约束。
6. 原生 Mongo/查询/聚合及 shell 的新限额见 [架构说明](../ARCHITECTURE.md#数据正确性和限额)。大查询和长脚本应在测试资产上确认行为后使用。
